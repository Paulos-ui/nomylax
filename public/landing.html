The gap

Autonomous agents should not hold unrestricted wallets.

Agent frameworks have solved capability. None of them solved authority. The moment an agent holds a private key, its worst possible decision and its best possible decision cost exactly the same to execute.

Unbounded authority

An agent handed raw wallet keys inherits the full authority of its owner. One malformed loop, one prompt injection, one hallucinated recipient, and the loss is the size of the treasury rather than the size of the mistake.

Unpredictable spend

Autonomous systems retry failed calls, escalate to expensive models, and buy the same dataset four times. Spend curves that look flat in testing turn steep the moment an agent meets the real world.

No financial governance

The stack is crowded with tools for what an agent can do. Almost nothing governs what it should be financially permitted to do, with limits that hold even when the model is wrong.

Safe mode

When behaviour changes, autonomy stops.

Three failed transactions, spend velocity above 200%, or a critical risk event moves the agent down a state. Recovery is deliberate: an owner decision, never an agent one.

State 01

Autonomous

The agent operates freely inside its constitution. Approvals settle without owner involvement.

State 02

Watch

Anomaly detected. Limits tighten, high-risk actions are held for review, the owner is notified.

State 03

Safe mode

New spending stops. Execution pauses, unknown recipients are refused, the treasury is preserved.

Security architecture

Security is architecture, not a feature.

A request passes through eight boundaries before it becomes a settled transaction. Each one can stop it.

L1Owner authorityThe human holds the keys and the capital. Every permission below is delegated, scoped and revocable.
L2Base permission boundaryOnchain spend permissions cap what the system can move, independent of application logic.
L3Policy engineDeterministic evaluation of limits, recipients, assets and reserves. No model in the decision path.
L4Risk engineSeven signals scored to NRS, compared against the agent's configured threshold.
L5Transaction simulationThe call is simulated before signing. Unexpected state changes fail the request.
L6ExecutionApproved actions are submitted to Base under the granted permission scope.
L7Post-transaction verificationSettled results are checked against the intent that was approved. Divergence triggers Safe Mode.
L8Audit proofRequest, decision, policy version and outcome are written to an append-only record.
